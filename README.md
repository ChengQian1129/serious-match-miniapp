# 认真匹配微信小程序体验版

这是一个可直接导入微信开发者工具的原生小程序 Demo。第一版以「认真匹配 · 关系底图」为入口，只负责关系偏好探索以及建立和维护资源池，不公开展示资料，也不提供站内匹配或聊天。用户操作会先即时写入本机，并在后台静默同步到微信云开发；同步失败不打断填写，后续操作会继续重试。

## 运行

1. 打开微信开发者工具。
2. 选择“导入项目”。
3. 选择本仓库的项目目录。
4. 使用项目当前配置的 AppID 运行。
5. 首次运行先执行 `npm install`，再在微信开发者工具中执行“工具 -> 构建 npm”。安装脚本会自动应用项目的 TDesign 选择器排版补丁。

## 云开发配置

1. 在微信开发者工具中开通云开发并创建环境。
2. 复制 `config/cloud.example.js` 为 `config/cloud.js`，再填写云环境 ID 和实际运营主体名称。`config/cloud.js` 已被 Git 忽略，不会上传到公开仓库。
4. 在云数据库中新建集合 `dating_profiles`、`assessment_sessions`、`assessment_reports` 和 `assessment_invites`。
5. 将这些集合的数据库权限设为客户端不可读、不可写。所有操作只允许通过云函数完成。
6. 在开发者工具中右键 `cloudfunctions/datingProfile`，选择“上传并部署：云端安装依赖”。
7. 编译后提交一份测试资料，在云数据库中确认生成了以当前用户 `OPENID` 为标识的记录。

`config/cloud.js` 未填写完整时，小程序不会假装上传成功：正式资料仍保留在本机，并提示先完成云环境配置。

界面以项目 `design` 目录中的 Dynamic Layer FREE Mobile App UI kit v5.1 为基础，复用注册流程、输入框、按钮、导航和底部操作栏规范，并针对中文小程序重新排版。主界面不使用 TDesign 默认视觉；TDesign MiniProgram 1.15.3 只负责选择器、底部弹层和确认对话框的交互底座，相关颜色、圆角和选择器排版已统一为当前黑白编辑式风格。

npm 依赖已经安装，构建产物位于 `miniprogram_npm`。

使用 Codex Computer Use 检查微信开发者工具时，如遇到 NW.js 窗口归属错误，请查看 [TROUBLESHOOTING.md](./TROUBLESHOOTING.md)。

## 已实现

- 首页和使用说明底部弹层，兼容新用户、体验中、个人档案草稿和已提交用户的不同入口
- 48 道、6 章正式关系探索题，统一的前后动效和可追溯的关系说明书
- 29 道基础资料与现实安排题：关系期待、现实协调、个人资料和匹配边界
- 不可变回答事件、`NA` / `SKIP`、版本化计分规则和逐条证据链
- 本机即时保存与后台串行云写入；后台失败不打断填写，后续操作自动重试
- 新设备可恢复已经保存的探索结果、正式问卷和个人档案
- 29 个问题组成的基础登记、现实安排和个人资料流程，自动推进与草稿保存
- 匿名资料预览
- 手动填写手机号和体验版隐私确认
- 通过 `OPENID` 隔离用户的云端资料保存与读取
- 云端资料修改、暂停、恢复和删除
- 新设备读取已提交的云端资料
- 保存成功页
- 我的资料、编辑联系方式、暂停、恢复和删除
- 扫码来源与关键行为的本地记录
- 云端失败时保留本机资料并支持重试
- 关系底图分组、历史报告版本和本人确认的分享名片
- 现实安排对照：见面时间、通勤、作息、家庭、财务、家务、宠物、饮酒和社交节奏

## Review 入口

- 产品与科学边界：`design/QUESTIONNAIRE_SPEC.md`
- 问卷定义与计分：`utils/questionnaire-definitions.js`、`utils/questionnaire-engine.js`
- 云端数据契约：`cloudfunctions/datingProfile/index.js`
- 页面与导航回归：运行 `npm test`

## 当前边界

- 尚未提供运营管理后台
- 不发送短信或微信通知
- 不使用微信手机号授权接口
- 手填手机号不验证号码归属
- 公开测试前仍需补齐运营主体联系方式、保存期限、用户权利等正式隐私政策

当前云函数会在服务端重新校验资料并从微信上下文取得 `OPENID`，不会信任客户端传入的用户标识。不要将 `dating_profiles` 开放为客户端直接读写。
