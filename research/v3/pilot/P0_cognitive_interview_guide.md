# Relationship Feature Model V3
## P0 Cognitive Interview Guide v0.1
### 在大样本之前先验证“用户究竟在回答什么”

> **日期**：2026-08-09
> **状态**：Ready for P0 preparation
> **建议**：3 个迭代波次，每波 8–12 人；不同波次重点不同，不要求每个人做完整 Mother Bank。

---

# 1. P0 的目标

P0 不验证：

```text
alpha
factor loading
matching accuracy
```

P0 验证：

```text
用户如何理解题干
用户调用了什么记忆 / 情境回答
选项是否覆盖真实答案
题目是否诱发社会赞许
两个 construct 是否在用户脑中其实是一件事
```

---

# 2. Interview 标准流程

对每个重点 item：

1. **Silent first response**
   先让用户正常作答，不要立即打断。

2. **Paraphrase**
   > “你觉得这道题用自己的话是在问什么？”

3. **Retrieval probe**
   > “你刚才回答时想到的是哪一次经历，还是一般印象？”

4. **Decision probe**
   > “你最后为什么选这个选项，而不是旁边那个？”

5. **Term probe**
   只针对高风险词：
   > “‘稳定关系’在你这里具体指什么？”

6. **Missing option**
   > “有没有一种真实情况你会想选，但这里没有？”

7. **Sensitivity / judgment**
   > “这道题有没有让你觉得存在一个明显‘应该选的正确答案’？”

# 4. Wave 1 必问 probes

## Readiness

对 `RR01 / RR04 / RR08`：

> “‘认真开始’、‘稳定关系’、‘让关系进入生活’在你看来分别是什么？”

检查：

```text
readiness
vs
desire
vs
marriage readiness
vs
available capacity
```

---

## Motivation

对 `IM-IN04 / IM-ID03`：

> “你觉得‘因为关系本身有吸引力’和‘这是我重视的人生目标’是一回事吗？”

对 `IM-NI01 / IM-EX01`：

> “这里更像是你自己觉得失败，还是别人给你压力？”

检查：

```text
negative introjected
vs
external
```

---

## Capacity

对 `CAP01 / CAP06`：

> “你说自己‘有时间’，这里的时间是实际能约出来，还是理论上有空？”

检查：

```text
availability
vs
willingness_to_sacrifice
```

---

## Follow-through

对 `FT07`：

> “先答应再做不到，对你来说通常是因为想让别人高兴、自己误判时间，还是别的？”

对 `FT-S01`：

> “如果选择提前说明，你觉得这是礼貌、责任，还是为了让关系可预期？”

---

## Uncertainty

对 `UA01 / UA10`：

> “你是在回答‘我会注意到变化’，还是‘我会觉得变化一定代表关系有问题’？”

检查：

```text
vigilance
vs
threat appraisal
```

对 `UA-S01`：

> “两天回复变慢，在你现实经验里本身算多大的信号？”

记录：

```text
scenario baseline interpretation
```

# 6. Wave 2 必问 probes

## Intimacy vs Space

对 `IDC03` 和 `PS01`：

> “关系太近让你不舒服，和只是想自己待一会儿，在你这里是同一件事吗？”

这是本波最重要的问题之一。

---

## Vulnerability vs Reliance

对 `IDC06 / IDC13`：

> “你可以讲自己的脆弱，但仍不想真正依靠别人吗？反过来呢？”

验证：

```text
vulnerability
vs
reliance
```

---

## Receiving Care

`IDC16`：

> “别人照顾你时不舒服，最主要可能是欠人情、失控、怕麻烦别人，还是不想被看见脆弱？”

检查 contamination。

---

## Support Need

`SN-S01`：

让用户先排序：

```text
first helpful
second helpful
least helpful
```

再问：

> “如果事情从工作失败换成生病，你的顺序会变吗？”

验证 context specificity。

---

## Signaling

`SS03 / SS05 / SS-S02`：

> “告诉别人我难受”和“告诉别人我希望他怎么做”，在你现实里容易程度一样吗？”

---

## Responsiveness

连续展示：

```text
RC-S01A
RC-S01B
```

问：

> “同一个问题，只是对方明确说自己想要的东西不同，你会不会真的换做法？”

重点验证：

```text
response_calibration
```

---

## Conflict

`CP01 / CR-S01`：

> “你想暂停时，是为了以后更好地继续，还是很多时候其实已经不想再谈？”

检查：

```text
pacing need
vs
withdrawal / abandonment of issue
```

# 8. Wave 3 必问 probes

## Ideal vs Acceptable

> “你选的理想状态，如果真人不是这样，你会真的不考虑，还是只是觉得没那么理想？”

如果用户反复把 ideal 当 hard：

> UI 必须进一步视觉区分。

---

## Hard Constraint

`L5-HC01`：

> “你说这是硬条件。如果其他方面都非常好，它仍然是一票否决吗？”

接着问：

> “‘不想优先介绍’和‘绝对不要介绍’对你是同一个意思吗？”

---

## Position Confidence

对未来育儿/财务：

> “你是在表达一个已经想清楚的规则，还是只是现在第一次被问到时的直觉？”

---

## Reciprocity

`L3-ST07 / L3-SB05 / L3-FO07`：

> “如果同样行为换成你自己做，这条规则还是一样吗？”

如果不一样：

> 追问现实责任差异，不使用“双标”措辞。

---

## Underlying Function

对 `L3-CT02 / L3-MG03`：

> “如果另一种表面方案也能满足你真正关心的东西，你会接受吗？”

例如：

```text
high-frequency messages
vs
low-frequency but predictable
```

# 9. 每波结束后的 Debrief

问：

1. 哪三道最难答？
2. 哪三道最像重复？
3. 哪道最让你觉得“有正确答案”？
4. 哪道你觉得现实里非常重要但我们没问到？
5. 哪道你觉得问得太早，自己现在根本不可能知道？
6. 有没有哪道涉及隐私但你仍愿意回答，只是需要更清楚说明用途？
7. 有没有哪道你不愿意在公开小程序答，但愿意和真人访谈说？
